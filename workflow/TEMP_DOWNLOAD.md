# 非 GitHub 一次性 APK 临时直链：交付契约与验收

状态：**未部署服务**。已有可选的 [Cloudflare R2 + D1 + Worker 服务实现](temporary-download-worker/README.md)及离线测试，但尚未取得真实托管/账号授权、完成实际 APK 上线或可用直链验收。已有测试不代表能生成用户下载链接。沿用项目现有正式签名、GitHub Releases 和 APK 下载回读门禁。

## 2026-11-02 过渡决定：先复用 SentinelX，Cloudflare R2 暂停

**这是应急交付通道，不代表下面的严格 APK 直链契约已通过。** 用户选择暂不推动 R2 订阅开通，不使用其计费服务；现有 Cloudflare Worker 源码、离线测试保留，不改写正式 Release 的交付事实。暂不创建 Cloudflare 托管资源。

已有 SentinelX 插件的 `sentinelx_sentinel_file_download_link` 可对**已存于在线主机且符合文件访问策略**的单个文件签发临时下载页，最长 60 分钟、最大 512 MiB，描述为完成一次下载后失效。当前只有用户的 Windows 主机 `win-my-ai-pc` 在线；关机、断网或文件不在允许路径内时，不可保证交付，不能假称云端无人值守。

2026-11-02 的**独立无敏感内容小文件**真实 HTTP 验证：30 字节测试文件，浏览器入口 `GET` 返回 `200 text/html`（下载页，不是 APK 直链）；通过 `POST` 取得 `200 application/octet-stream`、完整 30 字节；再次 `POST` 返回 `410`。这仅证明该次网络传输的一次性拦截，**没有**证明真实 Android APK 的 SHA256、并发竞争、手机安装升级或实际等满 60 分钟后的过期。不要把它写成 P0 已完成。测试令牌、真实交付令牌和完整 URL 均不得提交仓库或 CI 日志。

作为短期过渡的操作规则：

1. 正式版仍必须先通过原 GitHub Release、包名、签名、覆盖升级、资产回读与 SHA256 门禁，且不与其他会话重复发布。
2. 仅在 Windows 主机在线且允许访问时，将**同一 APK**置于 SentinelX 许可路径并重新核对文件大小与 SHA256；文件不得超过 512 MiB。不要在弱性能电脑上进行编译或完整测试。
3. 为 APK 生成独立测试链接 A（`expires_minutes: 60`），通过真实网络完成一次下载、原包摘要核对及再次下载拒绝，必要时并发测试；A 不得交付。随后另签独立用户链接 B，**不得先下载或预览 B**，经用户私密渠道交付；提示打开链接后还需在页面发起下载，且电脑需保持在线。
4. SentinelX 的 `GET` 是网页、并非本契约要求的 `GET 200 APK`；真实 60 分钟自然过期与 Android 手机安装未通过前，严格交付状态仍为 **blocked / provisional**。当用户再次要求无本地依赖的纯 GET 直链时，恢复评估独立云存储，另走计费授权。

## 必须具备的服务能力

1. 原始签名 APK 以相同 SHA256 上传到独立、可靠的非 GitHub 私有对象存储；不得从 GitHub URL 代理/重定向冒充独立托管。上传和下载不修改 APK 字节。
2. 服务按固定 APK 对象生成独立、不可预测的令牌；每个令牌服务端记录发行时间、绝对过期时间（60 分钟）、对象摘要、领取/消耗状态。校验和并发领取必须原子化，不允许两个并发请求得到完整成功响应。到期后必须不可用。
3. HTTPS `GET` 直接返回 APK 字节，拒绝 3xx 跳转（尤其不能跳向 GitHub）、登录页和预览页；成功响应完整长度及 SHA256 必须匹配正式发行 APK。无效/已用/过期令牌返回 404 或 410，绝不能再返回完整 APK。
4. 中断、连接断开、对象读取失败、并发请求和服务重启后的状态要有确定性恢复方案。只因服务端已写完字节并不严格证明手机已成功保存；应说明实际保证的是完整 HTTP 响应至多一次，而非“成功安装一次”。不得在浏览器预览、聊天链接扫描、`HEAD`、日志或健康检查中消费令牌。
5. 不能在 GitHub、CI 日志、Issue、PR、公开清单中保存用户令牌/带令牌 URL；令牌权限只读、只允许一份 APK；已发布版本与原始 GitHub Release 保持不变。

## 正式交付的正确顺序

1. 先完成项目既有源码/包名/versionCode/原签名/旧数据覆盖升级门禁，并实际回读 GitHub 正式发行的三份资产。
2. 将**相同 APK**传到非 GitHub 私有存储；存储端回读字节数与 SHA256，且其访问域名真实不属于 GitHub。
3. 为该 APK 单独签发 **测试令牌 A**。用 `verify_temporary_download.py` 同时发起两次 GET，要求恰好一个请求收到完整匹配字节，另一个被拒绝，随后第三次也被拒绝。测试 A 会被消耗，绝不能发给用户。
4. 单独签发 **用户令牌 B**；通过服务端可信管理接口只读核对 B 的对象、60 分钟过期时间与未消费状态（不要使用 GET/HEAD 消费 B）。把 B 的完整直链交给用户，不做会消耗 B 的“再测试”。
5. 过期验收必须使用额外的独立测试令牌，经过真实 60 分钟或服务可验证的时钟控制后确认失败。只查看 TTL 配置、响应时间或用户令牌 B 的元数据，不等于到期失效已实测。

工具调用示例（仅测试 A，敏感 URL 从 stdin 读取，不写入命令参数）：

```bash
python3 workflow/scripts/verify_temporary_download.py --consume-canary < /tmp/apk-canary.json
```

`/tmp/apk-canary.json` 的字段是 `url`、`size`（真实 APK 字节数）和 `sha256`（64 位小写摘要）。不要提交这个文件。退出 0 / `canary_verified` 仅表示**该测试令牌**的并发单次下载、字节/摘要及重取拦截已观察到；`expiry_60_minutes` 与 `recipient_link` 始终明确为未验证。其他状态不能交付。证据文件须删去 URL、令牌及服务端敏感响应。

没有正式托管、到期机制、签发权限或足够的验收证据时，此交付条件保持 `blocked`，不使用长期有效的 GitHub URL、第三方跳转链接或 ChatGPT 文件链接冒充完成。选择新供应商、账号、收费计划或扩大凭据权限时按项目授权边界处理。
