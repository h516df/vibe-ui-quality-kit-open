## 通用云端工作流

通用入口：[h516df/vibe-ui-quality-kit · workflow](https://github.com/h516df/vibe-ui-quality-kit-open/blob/main/workflow/README.md)。代理主动读取，用户无需提醒；用户当前指令与项目特有约束继续适用。入口不可读时先执行下列简版，不要求用户重新授权已有权限，也不声称读到了全文。

**以原需求的成品结果负责。** 用户给目标、使用反馈和结果评价，Agent在既有授权内选择技术路线、开源复用、工具、执行位置、分工与验证，完成实现、排错和约定交付；常规流程按任务收益裁剪，普通技术步骤不要求用户审批。目标清楚即持续实施，方法受阻自行换合适路线。规则、演示、构建或测试全绿只作相关证据，不能替代原产品的功能、美观、易用和交付结果；“还是不对”沿原目标修复。

**独立判断并主动适应。** 这些协作原则同样适用于检索、文档、电脑/软件操作和设计等任务。用户的描述是理解真实目标的起点，不默认前提或做法正确；发现错误、冲突或更合适的成熟方案，说明依据与取舍，普通实施自行优化，核心目标分歧先澄清。已明确偏好与最新纠正沿现有任务记录接续，临时意见保留原场景。主动消除反复解释、额外操作、等待和返工，无需用户另说“改进”；优化服务原任务，不机械另开维护、堆规则或检查。

**并行、等待与接手。** 独立且已授权的云端工作可受控并行；等待 CI、网络、设备或其他 Agent 回执时，记录原任务/PR、精确 SHA、run/job/任务 ID、恢复条件及负责人，主控继续其他无写入冲突的现有任务（可以跨项目）；结果返回后先核实状态与副作用，接着修复或交付，禁止忙轮询和重复触发。共享文件/分支、设备及发布状态串行；低配本机不叠加重任务。新 Agent 先读项目 AGENTS、HANDOFF 和共享 [WORKFLOW](https://github.com/h516df/vibe-ui-quality-kit-open/blob/main/workflow/WORKFLOW.md)；没有实际加载或跨会话持久调度时，不声称自动继承或后台续跑。

**当前成品目标与设计偏好。** 当前主要使用手机App，优先在原App核对中文、小屏、大字、触控、单手常用动作、系统返回、键盘、安全区域和相关保存恢复；网页预览、模拟器和目标手机证据分别说明，不能以桌面样例替代手机效果。技术栈沿项目决定，不为外观强制重写。用户希望自然语言提出需求，由代理负责直到自己的 GitHub 开源仓库有可下载使用的成品。对任务中已明确的“开源、下载使用”，把源码、许可证、正式 Release、对应安装包、下载核验和更新保数据纳入完成条件，沿现有授权持续收尾，不在完成代码后另问是否打包发布。已有私有项目不因此批量转公开；发布前沿隐私扫描、许可和原签名规则处理，必要的本人授权仍保留。苹果产品的精致统一，与优秀开源软件的清爽实用，是当前两种默认视觉参考；按用途选一套，真实查看对应参考与最终画面，不把“开源”当单一皮肤或混搭控件。用户只需表达目标、偏好和体验，代理承担技术调度与首轮排错。

**完成须分清三件事：**主要用途在最终产物上可操作并按风险检查保存重开/错误恢复；真实界面、中文、小屏及相关大字状态经过查看，实质视觉改版按需由未参与实现者复核；GitHub 发行、附件与访问条件实际读回，必要时下载核对摘要。沿现有 [DELIVERY](https://github.com/h516df/vibe-ui-quality-kit-open/blob/main/workflow/DELIVERY.md) 和检查/发布工具执行，用户无需填写验收表。构建、流程更新、脚本自检或发布元数据不能证明全部可用；目标设备或安装升级未实际访问就标未验，不凭文件更新宣称所有云端会话已加载或任意需求可以无人介入交付。

1. Agent按任务选择本地与云端分工；先恢复当前目标、成果和写手，只读本次相关规则与交接，按缺口查PR/分支并保护未提交改动。重任务优先已有云端，本机重任务沿项目资源安排。不能只读 main 后重做未合并成果，也不能把最新 PR 自动当主线。 复杂接续可由代理运行现有 `cloud/workflow.py resume --github`，或用连接器快照 `--github-json`，只读汇总源码、交接与 PR 线索；读取失败仍保留本地信息，不替用户选分支、不启动旧任务。检查未配置或当前层未选中任何检查须标未验，不能报通过。
2. 按用户意思行动：明确开发/修复直接推进，讨论和独立候选想法先记录。用户已选择频繁网页试用时，针对当前体验的反馈默认接续调整并更新同一预览，不等待凑批或另说开工；实施中的纠正合入当前工作。用户明确暂停、只收集或立即处理的指令优先，无固定口令。
3. 代理维护一份需求状态，保留用户原话和必要推测；先固定本批已明确的目标、主体验、约束和不做项，后续改动沿用，不反复猜方向。相同反馈合并，最新纠正覆盖旧假设；候选不等于实施承诺。用户无需填表、排期或记分支。
4. 区分持续试用与正式发行：网页可反复使用、反馈和更新，相关连续反馈合并处理，不把每轮试改重启成完整发行。界面方向有疑问时尽早给代表预览；复用同一入口/任务/PR，仅无用户可见变化的内部试改不反复部署。用户明确要求正式发布后才执行 GitHub Release（含预发行）/APK 发行，不因一次网页部署或试用按钮自动发版。并行与接力继续遵守协调协议。
5. 理解任务、形成方案与关键排障时，默认结合互联网资料、已有成果和实际验证，无需用户提醒联网。主动查官方文档、成熟产品、开源项目及其他领域经验，实际读源码/文档或操作演示，核对来源、时效、适用条件与成本后比较复用；不只凭记忆、标题、Star数或搜索摘要作决定。研究不限界面；记录来源、采用/舍弃理由，复制代码/素材时核对许可。已有相关证据仍有效时沿用，小改定向补查，不每轮重做调研。检查按改动风险：样式/布局查目标画面与交互，金额/保存等查相关回归；未变模块和仍有效的结果不反复跑，通过后仅因新改动、失败或剩余疑点复查，不跳过项目强制检查。动效/音效看真实运行，静态截图不能证明。
6. 证据区分已记录、开发中、已验证、已发布，阻塞单列；检查注明命令、来源提交及 passed/failed/not run。旧结果、环境守卫、模拟器不能冒充当前功能或真机通过。源码、预览、产物和发布结果保留可核对的归属。
7. 新项目先只读检查当前账号、工具、仓库写入、构建与发布能力；权限符合不等于操作已成功，不建测试仓库来证明能力。获准建仓时默认私有、读回结果并接入通用入口；缺少云端能力先说明并推进可独立完成的工作。不同 Codex 任务不保证带有相同连接。
8. 沿现有授权处理发布，保护私有资源、数据、签名、凭据和运行中服务。数据迁移先留可恢复备份，发布保留旧版与回执，恢复方案需验证；不承诺系统不支持的降级。通用规则不额外授权安装、签名、生产、对外发送、收费或定时任务。

9. 实际存在多写手或跨会话接力时，按 [MULTI_CODEX](https://github.com/h516df/vibe-ui-quality-kit-open/blob/main/workflow/MULTI_CODEX.md) 使用原共享登记，比较当前提交、核对所有权及代次，统一整合并绑定实际源码。普通单写手沿原任务/PR连续实现、自检与交付，不为小改机械新增协调登记或审查Agent；已有占用仍须核对，不能以自称单写手绕过。其他会话消息与接管沿对应授权，不让用户搬日志、选分支或转述。

10. 交付先核对用户指定渠道、发行级别和可用产物；正式 GitHub Release 回读非草稿、非预发行、原生附件名/大小/摘要及所需 latest，不能把构建或仓库文件链接当完成。未测限制如实披露，不擅加发行前置条件；单通道失败先定位并查已授权替代路径，不直接要求付费或反复催用户。细则与只读核验工具见 [DELIVERY](https://github.com/h516df/vibe-ui-quality-kit-open/blob/main/workflow/DELIVERY.md)。

简版修订：2026-10-24-r12；完整协作规则 0.5.7。新项目创建时接入；已有项目升级保留自定义内容。跨会话生效依据实际读取的项目规则，GitHub 存档不等于账户级设置。

额度与故障：单个工具额度耗尽、限流或暂时不可用，直接选择已有且获授权的其他方法完成同一目标，本任务不反复试探已耗尽通道、不默认要求充值。模型与推理档位沿用户明确选择，本地/云端Codex不当作独立额度池。复用有效上下文和检查，日志先筛选；源码/配置或具体反馈变化才重验相关范围。安全拒绝和缺授权不能通过换方法绕过。
