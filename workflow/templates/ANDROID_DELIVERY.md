# 安卓首发与覆盖更新验收

这是可选模板，由代理结合项目填写；勾选必须有实际证据。各项分别记录状态，不把整表或全部设备验收自动当作用户指定 GitHub 正式发行的前置条件。接入工具、云端构建、下载和实体手机安装分别记录，不要求用户管理此表。

## 先确认交付路线

- [ ] 包名、最低系统、架构和私有源码仓库已确定。
- [ ] 发布目标：应用商店，或独立 APK + HTTPS 更新清单；现有渠道优先复用。
- [ ] 给普通用户的公开下载不要求 GitHub 登录；私有测试分发的授权流程另行说明。
- [ ] 云端构建已实际成功；环境/守卫检查不能冒充 APK 编译。

## GitHub 发行（采用此渠道时）

- [ ] 按用户要求的正式版/预发行发布；原生附件包含 APK，不只提供源码 ZIP 或仓库文件链接。
- [ ] 回读 draft/prerelease、所需 latest、准确标签 SHA，逐个核对附件名/状态/大小/SHA256/下载地址。
- [ ] 使用 [DELIVERY](https://github.com/h516df/vibe-ui-quality-kit-open/blob/main/workflow/DELIVERY.md) 和只读 verify_release.py 生成当前回执；真机/匿名下载/长期恢复未验证不冒称已通过。

## 签名与恢复

- [ ] 使用项目长期签名，首次配置后不随新 Codex 会话重建；记录公开证书指纹。
- [ ] 签名材料有受控长期保存与独立恢复路径，已验证恢复后的证书与签名一致；临时 VM 和单份 Secrets 不当作已完成恢复验证。
- [ ] 不把私钥、密码或 token 放在源码、聊天、普通 artifacts、更新清单或公开附件。
- [ ] 发布产物的包名、versionCode、证书、正式属性、架构及最低系统已核对。

## 更新实现与发布

- [ ] 对应 App/渠道的清单入口、中文说明、版本号和下载地址匹配，不依赖多 App 仓库的全库 latest。
- [ ] HTTPS 下载，校验来源、字节摘要、包名、签名与版本；完整包验证通过前不交给安装器。普通 SHA256 文件不能单独证明来源真实。
- [ ] 无更新、断网、取消、下载失败及有更新可用的场景已检查；更新失败时旧版本可继续使用。
- [ ] 系统要求的安装授权与安装确认有清晰引导，不承诺静默安装。
- [ ] 先发布并实际回读/下载验证产物，再切换更新清单，失败时不指向不完整版本。
- [ ] 保留上一版产物、清单/部署回执及恢复方案。Android 一般不允许低版本覆盖；回退问题通常需以更高 versionCode 发布修复版，不承诺用户能直接降级。

## 数据与设备

- [ ] 数据结构升级、备份/恢复及中断恢复已验证；网页数据迁入安卓若需要，单独提供实际迁移路径。
- [ ] 旧版本安装 → 创建合成数据 → 安装新版本 → 数据与主要功能仍正常。
- [ ] 至少一台目标实体手机实测安装权限、覆盖更新与数据保留；云端模拟器通过不能代替此项。
- [ ] 每项保存命令、来源提交、产物摘要/部署标识或设备结果，区分 passed / failed / not run。

参考：[Android 应用签名](https://developer.android.com/studio/publish/app-signing)、[版本规则](https://developer.android.com/studio/publish/versioning)、[独立分发与安装授权](https://developer.android.com/distribute/marketing-tools/alternative-distribution)。
