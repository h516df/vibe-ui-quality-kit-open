# 当前任务或批次

- 用户意图与阶段：讨论 / 收集 / 实施；明确实施不再要求开工口令。
- 需求池及本批条目（链接，避免重复维护状态）：
- 目标 / 用户场景 / 具体数字或操作例子：
- 本批已明确且应保留的要求 / 不做项（几行即可）：
- 完成条件（通常 2–5 条）：
- 本批边界、重要依赖与合理假设：
- 代表体验 / 固定预览入口与本轮可试调整：
- 正式发行授权及状态（与网页部署分开；已有授权不重复询问）：
- 相关网上/GitHub/官方来源、实际查看/操作与采用/舍弃理由（已有有效证据沿用，新增问题定向补查）：
- 会话/任务 ID、角色、协调登记代次与范围（多会话时）：
- 分支、独立工作区、基线与 PR：
- 本次变化影响的检查、可复用的未变证据及实际结果（命令、来源提交、passed/failed/not run）：
- 交付预览 / 产物 / 部署回执：
- 阻塞与下一步：

由代理维护；简单改动不强制新建文档。顺序接力确认前一写手停止后沿用分支；并行会话独立分支/工作区，各自任务记录，整合者汇总公共交接；纠正当前任务及时处理，新增独立想法回需求池。一批可以内部拆分提交和检查，网页试用阶段持续更新同一入口；用户明确要求后集中完成正式发行。

## 交付完成条件（代理补全）

- 用户指定的交付位置、发行级别与下载者访问条件：
- 用户实际需要的产物/附件，而非源码归档或临时替代：
- 真实来源 SHA、最终 URL 与发布状态/附件回读方法：
- 失败通道、已经核对的授权内替代路径与仍需本人处理的不可替代事项：
- 未测限制单列；不自动扩为用户未要求的发行阻止条件。
