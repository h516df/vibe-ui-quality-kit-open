# 当前任务或批次

由代理维护，简单改动沿现有记录，不机械新建文档。用户只讨论目标与使用反馈，不填写技术表格；已明确实施就直接推进。

## 当前约定

- 用户要的结果、使用场景与本批阶段：讨论 / 收集 / 实施。
- 原需求池或既有规格链接：已有内容引用即可，避免复制两份状态。
- 最近纠正与本批变化：新增 / 修改 / 移除；被替换的旧假设明确失效，其余已确认约定继续保留。
- 可观察完成条件（通常2–5条）：包括用户实际需要的产物、交付位置、发行级别和下载者访问条件；源码归档不替代安装包。
- 重要约束、代理推荐默认、核心未决问题与本次不做项：只保留真正影响实现的内容。

## 执行与交付

- 当前写手、会话/任务、分支、工作区、基线与PR；并行/接力时记录协调代次和范围。
- 下一步第一项操作、相关入口/文件/符号；优先读取与当前问题相关的上下文，再按实际缺口扩展。
- 本次受影响检查、可复用的未变证据及实际结果：命令、来源提交、passed / failed / not run；需求纠正仅使相关旧证据失效。
- 固定预览或实际产物入口：沿同一结果迭代，内部提交/检查不增加用户辨认版本的负担。
- 正式发行授权、最终URL、真实来源SHA、发布状态、附件回读与来源映射；已有授权不重复询问，预览更新与正式发行分开。
- 相关来源与采用理由：已有有效研究沿用，新增问题定向补查。
- 阻塞、已核对的授权内替代路径、未验范围及下一步；只有确需本人操作时留下最小动作，不把所有未来检查变成当前门禁。

顺序接力先确认原写手已停，并核对当前源码及最近纠正；并行会话各自隔离，整合者维护公共交接。独立新想法进入候选池，当前口径纠正直接更新本批；状态变化不重启一套规格、部署和全量回归。
