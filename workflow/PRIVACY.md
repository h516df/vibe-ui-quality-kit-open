# 隐私与凭据检查

**为什么有这一条**：真实资料、账号信息和密钥一旦进入测试样例或文档，就可能随仓库公开。样例只使用合成数据；说明风险时也不复制真实地址和私人资料。

**结论：公开或对外分发之前，必须跑一遍扫描，而不是靠人眼看。**

## 怎么跑

```bash
python workflow/scripts/privacy_scan.py <仓库根目录>
python workflow/scripts/privacy_scan.py <仓库根目录> --json > privacy-report.json
```

退出码 `0` 是没有问题，`1` 是有命中需要处理。命中按类别分组，给出 `文件:行`、片段和处理建议。

## 会检查什么

| 类别 | 例子 | 处理方式 |
| --- | --- | --- |
| 本机绝对路径 | `%LOCALAPPDATA%`、`$HOME` 下的绝对路径 | 改成占位符或从 `ANDROID_HOME`、`USERPROFILE`、`DSH_HOME` 等环境变量读 |
| 手机号 / 身份证 / 银行卡 | 11 位手机号、18 位身份证、16–19 位长数字 | 换成 `13800138000` 之类的示例值 |
| 邮箱 | 真实邮箱地址 | 换成 `example.com` |
| 私钥与令牌 | PEM 私钥内容、平台访问令牌 | 立刻作废，仓库里只留占位符 |
| 凭据赋值 | `password=<placeholder>`、`token=<placeholder>` | 只留环境变量或示例值 |
| 密钥文件 | `*.jks`、`*.keystore`、`*.p12`、`keystore.properties`、`.env` | 不进仓库；签名材料单独受保护存放 |
| 疑似真实地址 | 省市区 + 路街 + 门牌号 | 尤其注意 `test/resources`、`fixtures`、`samples` 目录 |

长哈希串里的数字不会误报成手机号；字符串类型声明、版本号和依赖锁文件里的第三方作者邮箱也已排除。

## 豁免

确属安全示例的行，在行尾（或上一行）加 `privacy-ok`：

```kotlin
val demoPhone = "13800138000" // privacy-ok 公开的示例号码
```

## 什么时候跑

- 仓库从私有转公开之前——**这是硬门槛**，公开的是全部历史，不是眼前这份文件
- 发布正式包或对外交付之前
- 新增测试样例、验收截图、demo 数据之后
- 新增脚本、把本机路径写进代码之后

## 已经公开了才发现命中怎么办

1. 先改当前文件（换掉真实值），推到默认分支，越早越好
2. 再判断历史：命中项在旧提交里的话，改写历史或另建干净仓库，按「仓库转公开」的流程重新评估
3. 涉及密钥或令牌的，先作废再改文件，顺序不能反

## 截图也要过一遍人眼

扫描器看不到图片内容。界面截图里常带昵称、真实店名、带店名的外卖页、地址栏。公开前把这些截图逐张看一遍，或者直接不放进仓库。
